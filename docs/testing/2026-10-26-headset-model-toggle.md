# Headset adaptive-provider comparison

**Implemented — MiniLM default.** New study sessions and development quick tests start with Local MiniLM. Open headset **Settings** and use the **Model** button to switch between **Jev** and **Local MiniLM**. Settings pauses an active search; switching is rejected while a search is running unpaused. Close settings and resume using the existing pause flow. Local mode shows Connecting, Ready, or Unavailable. Both use the same adaptive-v4 state, seven strategy choices, capability masks, prepared audio, voice condition, freshness checks and final geometry/target gates. This selects the active assistance provider, not a shadow prediction.

The Mac hosts MiniLM; the weights are not embedded in the headset. Run from this checkout:

```sh
python3 tools/local-jev/headset.py
```

The helper starts or reuses the pinned `20261026-minilm-reassurance-v8` CPU service on Mac loopback port 8766 and adds an ADB reverse tunnel to the authorized headset (USB or Wi-Fi ADB). Keep the Mac awake and connected. Rerun after reconnecting ADB or restarting the Mac. With multiple devices, provide `--serial`. It refuses to replace a service with an unexpected contract/checkpoint and never resets ADB. Service logs are under `~/.local/share/follow-my-voice-models/headset-service/`; the helper records its launched process ID there. It starts no trials. No cloud API key is sent to the local endpoint.

A local connection check verifies the assistance scope and checkpoint version. Each accepted decision also verifies the response decision ID and version, and retains the checkpoint SHA-256. Unavailable, wrong-model, malformed or timed-out responses cannot fall back to cloud Jev or baseline search hints. Pending requests and queued guidance are cancelled when switching; provider identity and the policy epoch invalidate stale work. The local connection is rechecked while selected. Baseline ignores the provider selection. New participant reset restores MiniLM. Jev is an explicit opt-in for the current participant. Adaptive/Baseline remains a development-only control.

**Comparison scope:** the selected provider makes two sequential decisions: `assistance` selects the action, then `assistance_phrase` selects exact wording from that action’s truthful, prepared alternatives. Observation skips the phrase stage. Both stages use the same provider; `observe_2s` and `observe_4s` are removed. Unity measures direction, enumerates valid alternatives and checks freshness; it does not rank the winning adaptive action or phrase. Shared opening/confirmation/expired-trigger feedback and safety remain explicit local overrides. Actual round playback history (including the opening) reaches the phrase stage to discourage exact repeats. In MiniLM mode, round feedback comes from the prepared local catalog and Jev transmission/interruption advisors and warmup are disabled. Selecting Jev enables its advice paths. Voice enrollment/preparation can still use external services; this is not a fully offline mode. Switching mid-trial preserves the participant's real cue/outcome history; it is an informal paired development test, not randomized study evidence. For a cleaner comparison, use separate quick-test runs, the same voice and the same scenarios, and alternate which model you try first.

**Recorded evidence:** request/response traces include `provider` and `model_version`; local responses retain probabilities, probability semantics, source and checkpoint hash. Application traces retain provider and request ID; playback links use that ID. Provider changes are explicit events carrying the actual study/development flag. `assistance_provider_at_summary` is only the final selection, never a claim that every decision in a mixed run came from it. The Trial Viewer model inspector labels each request's provider, checkpoint version, probabilities and playback. Older traces lacking provider tags retain their historical Jev interpretation. The shadow comparator excludes active local traces so they cannot become mislabeled cloud comparisons; the earlier observer was stopped when active switching was introduced.

## Current default and hint-frequency verification (adaptive v4)

**Historical verification — single-stage v4:** elapsed silence was included in MiniLM's features. Authored training examples vary elapsed silence and the offered brief/explicit capabilities; the model can offer further help during unresolved progress. All seven diagnosed silent requests now select an offered speech strategy; six existing behavior probes and 192 closed-gate cases pass. Production C# calls to that v4 service returned observation during independent progress and orientation during stalls. These are regression checks, not wearer validation.
