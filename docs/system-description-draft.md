# System Description

## Apparatus

The mixed reality system was built in Unity 6 for the HTC Vive Focus Vision standalone headset. The application targets Android ARM64 using the Universal Render Pipeline, OpenXR, XR Interaction Toolkit, XR Hands, AR Foundation, and HTC's VIVE OpenXR package. The headset was used in video see-through mixed reality mode, allowing participants to view the physical table and surrounding laboratory environment while virtual search stimuli and interface elements were rendered into the scene. Passthrough rendering was initialized through HTC's OpenXR passthrough API as an underlay layer so that virtual content could be composited over the real world.

Eye gaze was used as the primary input signal for both selection and assistance. The headset's eye-tracking pose was routed through Unity's XR Interaction Toolkit gaze stack. A tracked pose driver controlled the gaze interactor transform, and an `XRGazeInteractor` cast a ray into the mixed reality scene to determine which virtual object was currently being attended. The system could optionally render this ray as an orange line for debugging or participant-facing feedback, but the visual ray was independent of the underlying gaze tracking, dwell selection, hint generation, and telemetry logging. Therefore, gaze data and hover state could continue to be collected when the ray visualization was hidden.

The physical setup required a table surface in front of the participant. Table localization was handled through a VIVE-specific plane detection bridge. Because the Vive Focus Vision does not provide an AR Foundation `XRPlaneSubsystem` on device, the project used HTC's native `PlaneDetectionManager` to retrieve room-setup planes and convert them into Unity `GameObject`s with mesh colliders. Horizontal upward-facing planes were assigned to the placeable-surface layer and used as candidate support surfaces for the search layout. Once the participant tapped a detected surface, the system used the nearest horizontal plane as the anchor for the virtual bookshelf task.

## Mixed Reality Search Environment

The virtual task environment consisted of two adjacent bookshelf units placed on top of the detected physical table. The bookshelf geometry was generated procedurally at the start of a run and cached for all subsequent rounds so that the spatial layout remained stable throughout the session. Each bookshelf column was oriented to face the participant based on the table plane axes and the participant's camera position. The system snapped the shelf orientation to the nearest table axis, computed a shelf-right axis perpendicular to the facing direction, and stored the resulting orientation so that all objects faced outward toward the participant.

Each bookcase was modeled as a seven-row structure with side panels, a back panel, and horizontal planks. The total bookcase height was 0.84 m, yielding seven rows of approximately 0.12 m each. The bookcase depth was 0.18 m. The two bookcase columns were separated by a 0.03 m gap, with each column constrained to a minimum width of 0.30 m and otherwise scaled to the detected table width. Planks and panels were 0.012 m thick. The generated shelf objects used box colliders and visually resembled simple wooden or neutral support geometry rather than decorative furniture. This provided a repeatable spatial frame while keeping the visual emphasis on the search objects.

The search objects were arranged into a fixed 7 row by 2 column spatial grid corresponding to the two bookcases and seven shelf levels. Within each shelf cell, multiple objects were distributed horizontally across the inner shelf width. For the current task, each round contained 56 virtual objects, yielding four objects per shelf cell across 14 shelf cells. Spawn points were computed from the cached shelf geometry and reused across rounds. This design ensured that every participant experienced the same spatial density, shelf structure, and target search space once the initial physical table placement had been resolved.

Each virtual object was approximately 8 cm in scale and represented one conjunction of shape and color. The stimulus set contained six shapes: sphere, cube, pyramid, cylinder, star, and capsule. Spheres, cubes, cylinders, and capsules used Unity primitive meshes, while the pyramid and star meshes were generated procedurally. The color set contained four colors: red, blue, yellow, and purple. Together, these produced 24 possible shape-color combinations. Each object received a per-instance material using the project interactable shader, with its base color set to the assigned color and edge-highlight properties available for gaze feedback.

Objects were instantiated from a common prefab and then post-processed at runtime. The post-processing step removed stale prefab renderers and colliders, replaced the mesh with the selected shape, applied the selected color, added an appropriate collider, set the object to the gaze-interactable layer, and attached metadata describing its shape, color, shelf row, and shelf column. Objects were made kinematic and gravity was disabled so that the array remained stable and repeatable. Each object also received an `XRGrabInteractable` configured to allow gaze interaction while disabling gaze selection and gaze assistance from the default toolkit. This allowed the gaze interactor to generate hover events without allowing standard toolkit selection mechanics to interfere with the experimental dwell-selection logic.

## Task and Round Structure

The experiment was implemented as a deterministic conjunction-search task. In each round, the participant was instructed to find one target object defined by a color and a shape, such as a red sphere or purple capsule. The target appeared among 55 distractors in the 56-object bookshelf array. Participants selected objects by dwelling on them with their eyes rather than by using a controller grab. A correct dwell capture advanced the task to the next round, whereas an incorrect capture was logged as a wrong selection and the round continued.

A complete session contained 14 rounds. The challenge set was generated with a fixed random seed so that all participants received the same target order, distractor composition, and object arrangement. For each round, the object set contained one target, 13 distractors sharing the target color, 13 distractors sharing the target shape, and the remaining distractors drawn from shape-color combinations sharing neither the target shape nor target color. This composition made the task a conjunction search rather than a simple feature search, because participants could not solve the task by attending only to color or only to shape.

The task began when the participant tapped a detected plane. This first spawn event was intercepted by the experiment manager and used only as a session-start trigger. The trigger object was destroyed, the shelf layout was built, the deterministic challenge set was loaded, and the first round was prepared. Before each round, including the first round, the participant saw a fixation cross and the upcoming target text. During this transition phase, the voice assistant announced the next target. After the transition interval, the cross disappeared, a brief randomized blank pause occurred, and the object array for the round was spawned. This same transition structure was used between all rounds so that participants received the target instruction during a controlled fixation period rather than during active search.

During active search, the current target remained available through the task interface. When the participant looked at an object, the gaze interactor reported a hover event. The dwell-selection manager then accumulated dwell time on the currently hovered object. If the participant maintained gaze on the same object for 1.6 seconds, the object was captured. The object's edge highlight progressively intensified during dwell, shifting from a dim warm orange rim to a brighter yellow-white glow. On capture, a brief flash and a non-spatial confirmation sound were played. If the captured object matched the current target shape and color, the round ended, all current objects were destroyed, and the next transition began. If the object did not match the target, the wrong capture was logged and the participant continued searching.

## Gaze-Contingent Assistance

The system included a voice assistant that delivered condition-dependent hints during active search. The assistant was initialized at runtime after loading the text-to-speech API key and was coordinated by a voice controller attached to the object-spawner root. The voice controller created and connected the gaze coverage tracker, context builder, speech synthesizer, and hint generator. It also listened to game events so that ongoing speech could be stopped at round boundaries, target announcements could occur during fixation-cross transitions, and hints could be suppressed while the game was not in an active search state.

The current study alternated assistance conditions by round. Odd-numbered participant-facing rounds used a gaze-unaware condition, and even-numbered rounds used a gaze-aware condition. In both conditions, the assistant spoke during the task, but the information available to the hint generator differed. In the gaze-unaware condition, the assistant produced generic encouragement and pacing support without using gaze state or revealing whether the participant was close to the target. In the gaze-aware condition, the assistant used the participant's current gaze target and near-target evidence to provide proximity-style feedback. The gaze-aware feedback was intentionally constrained to warmer-colder style language, such as off-target, on-track, or very-close feedback, rather than direct statements of the target's exact shelf, side, or coordinate.

The gaze-aware classifier combined several signals. It first attempted to resolve the currently hovered object through the gaze interactor's hover list. If a valid object was being attended, the system compared that object's shape, color, shelf row, shelf column, and world position with the current target. The hint generator also used geometric evidence from the gaze ray, including angular alignment with the target and distance from the ray to nearby candidate objects, to tolerate small eye-tracking or collider misses. A tight spatial threshold was used for very-close evidence, and a broader distance and angular threshold was used for on-track evidence. Recent near-target evidence was remembered briefly to prevent hints from rapidly switching between warm and cold because of momentary gaze jitter.

A conservative guard was used to prevent misleading feedback. If the participant's current gaze resolved to the opposite bookcase from the target, the gaze-aware condition forced an off-target response even when other signals were noisy. This was done because an incorrect "warm" hint on the wrong side of the search space would be more damaging than a conservative cold hint. The result was a gaze-contingent assistant that reacted to where the participant appeared to be looking while avoiding direct target-location disclosure.

The assistant speech was synthesized through an external text-to-speech service and cached locally for reuse. Spoken target announcements, congratulatory messages, wrong-selection cues, and hint utterances were treated as distinct speech contexts. The system stopped ongoing assistant speech at successful captures and before new round announcements so that audio from one task phase did not overlap with the next.

## Gaze Tracking, Feedback, and Telemetry

The gaze pipeline served three roles: interaction, assistance, and measurement. For interaction, gaze hover events drove dwell selection. For assistance, gaze state and object metadata informed the gaze-aware hint generator. For measurement, the same gaze and hover state were written to structured logs for later analysis.

The dwell selector ran after normal interaction affordances so that the project-specific gaze highlight could override residual controller or toolkit highlights. While the participant looked at a candidate object, material property blocks were used to modify edge-highlight and emission properties without creating new shared materials. This allowed the system to provide continuous visual feedback during dwell while preserving the original object colors used for the search task. The dwell selector also exposed the current dwell progress and dwell target for logging.

A per-frame gaze logger wrote a CSV file during active gameplay. The log included timestamp, frame index, gaze origin, gaze direction, gaze rotation, left-eye and right-eye position when available, eye openness values when available, fixation point when reported by the XR device, hovered object name, hovered object shape, hovered object color, hovered shelf level, target-match status, dwell progress, current target shape and color, round index, game state, ray-visibility state, blink state, and cumulative blink count. Blink detection used smoothed bilateral eye-closure signals and duration thresholds to avoid counting brief tracking noise or one-eye squints as blinks.

In addition to the per-frame gaze log, a trial-level logger recorded discrete game events and wrote per-run summaries. Event logs included game start, objective start, correct captures, wrong captures, game completion, dwell durations, target identity, selected object identity, shelf metadata, and task timing. At the end of a run, the participant was prompted to complete a NASA-TLX workload rating. The resulting data structure allowed the analysis to relate task performance, gaze behavior, assistant condition, wrong selections, workload, and subjective experience at the round and session levels.

The combination of deterministic stimulus generation, stable shelf geometry, gaze-dwell interaction, condition-dependent assistant speech, and synchronized telemetry was intended to make the application function as a controlled mixed reality research instrument rather than a general-purpose game. The system design allowed the study to compare gaze-aware and gaze-unaware assistance while preserving the same visual search task, object set, spatial layout, selection method, and logging pipeline across conditions.
