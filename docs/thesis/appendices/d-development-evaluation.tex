\chapter{DEVELOPMENT EVALUATION}
\label{app:development}
\label{sec:development-evaluation}
Before participant data collection, the system was evaluated in two ways: automated software verification and recorded development sessions on the headset. Both describe how the apparatus behaves; neither provides participant results or a voice-condition effect.

\section{Software Verification}
Software verification records document the apparatus alongside the development recordings in Section~\ref{sec:development-results}. A verification run on October 20, 2026 passed schedule and voice-isolation checks confirming one practice trial in the first assigned voice, two measured blocks, and the nominal-angle quotas. The same run passed 38 trial-export tests and seven workload scoring and plotting tests, and the Android application was built, installed, and launched successfully. These test counts come from that run and were not re-executed for this manuscript. The November 2, 2026 version, schedule v10 with layout v7, includes the pre-cue snapshot, balanced direction and height allocation, equal trials on each object plane, and bounded local clutter. Its schedule and layout checks pass across 200 participant identifiers, both voice orders, and seven eye origins, and all 271,600 generated layouts were accepted within the attempt limit. Readiness timing has not yet been measured on the headset. On the same date, a simulated participant drove the Unity application through one complete 97-trial session in each voice order, through export and analysis, and each exported measure was compared with the simulator's record of what occurred. This run exercised the software path only. It involved no wearer, and intake providers, audio, and the headset connection were simulated. Fixation and saccade counts disagreed with the simulated truth under uneven frame timing, so these detectors remain unvalidated.
