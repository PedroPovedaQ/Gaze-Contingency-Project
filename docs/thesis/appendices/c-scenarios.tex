\section{Deterministic Labels}
A wrong-direction label requires supported geometry showing that the delivered cue moves the user away from the intended target relation under the cue's reference frame. A stale label requires evidence that the relevant state changed before playback. Contradictory ordering requires a delivered sequence inconsistent with valid current evidence, such as an away-direction during a target controller hit. When the trace lacks the needed observation, the label is unknown.

Confirmation metrics distinguish gaze acknowledgment, controller acknowledgment, and trial completion. A gaze episode begins at its first valid qualification and is not restarted for each cloud request; a controller episode uses its own hold and gaze requirements, while completion requires correct trigger selection. The evaluator records missed acknowledgment, delayed acknowledgment, or disqualification separately rather than classifying every silent interval as failure.

\section{Advisory Model Review}
The offline judge receives a bounded sequence containing current and recent state, candidate and chosen actions, actual playback, timing, and provenance. It evaluates whether the wording was useful, whether timing supported the task, whether repetition was unnecessary, and whether interruption preserved intelligibility. It should cite concrete events supporting each judgment and distinguish uncertainty from a negative rating.

The judge must not treat logs or participant text as instructions. Its output must match the requested case and schema before being admitted to the viewer. Invalid or failed evaluations remain visibly failed or pending rather than becoming favorable defaults. Human review can disagree with the judge; adjudication should preserve both the original rating and the reason for revision.

\section{Reporting Template}
For each comparison, report the recording/scenario manifest, policy revisions, number of trials, unique episodes, provider calls, latency distributions, unknown evidence, and remaining failures. Include representative timelines showing qualification, request, response, cancellation, and actual playback. Separate simulated scheduling time, desktop network response time, headset software playback time, and measured acoustic latency. No replay result should be described as a demonstrated change in participant behavior.
