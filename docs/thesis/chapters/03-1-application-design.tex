\chapter{METHODOLOGY}
\label{ch:system}
This chapter outlines the application development, experimental design, and data collection methods used in Follow My Voice to evaluate how the voice delivering spoken guidance, either an SSV or an SAV chosen by the participant, impacts task performance, workload, and engagement, with object search as the task. The guidance voice is the independent variable, and the search task and the gaze-contingent agent guidance system remain the same across conditions. The application is created in Unity 6 (6000.3.10f1) for the HTC VIVE Focus Vision headset (2448 $\times$ 2448 resolution per eye, 90-Hz refresh rate, up to 120$^\circ$ field of view, integrated eye tracking) using the Unity OpenXR Plugin and the HTC VIVE OpenXR integration~\cite{htc2026focusvision}.

In the experiment, after a short practice after gaze calibration, in which participants look at and select each of the six shapes once without voice guidance, participants complete two counterbalanced blocks of 48 trials, with each block representing a different voice condition. Each trial begins in the same way: participants search for a specific target among colored geometric objects on eight surrounding object planes while the LLM based agent guides them with spoken directions. Participants do not know what the object is ahead of time. The source code is available at \url{https://github.com/PedroPovedaQ/Gaze-Contingency-Project}. Performance and eye-tracking data are collected through the headset application, and perceived workload, voice preference, and task engagement are captured through questionnaires.

\subsection{Apparatus and Search Scene}
The application is developed in Unity 6 (6000.3.10f1) using the Unity OpenXR Plugin (1.16.1), HTC VIVE OpenXR integration (2.5.1), and Unity XR Interaction Toolkit (3.3.1). It is deployed as a standalone Android ARM64 application on the HTC VIVE Focus Vision head-mounted display, with rendering performed locally on the headset using the Universal Render Pipeline (17.3.0). The study uses the headset's virtual-reality configuration, in which the headset supplies head-pose and eye-gaze tracking and the tracked right-hand controller supplies pointing and trigger input. Network access supports voice preparation and the connection to the lab computer that runs the decision model. It is not used to stream rendered frames from a host computer. HTC specifies 2448 $\times$ 2448 pixels per eye, a 90-Hz standalone display refresh rate, and a field of view of up to 120 degrees~\cite{htc2026focusvision}.

The search task takes place in a neutral virtual room with a gray floor and four distant gray walls (Figure~\ref{fig:virtual-room}). A yellow platform-esque circle on the floor is centered on the participant, and its 1.5-m radius ends where the objects begin. The objects are arranged on eight surrounding vertical object planes that are not drawn in the participant's view. The participant perceives they are in a circle with objects surrounding them. The study configuration contains 168 objects per trial, or 21 per section, at a default radius of 1.5~m from the seated origin. The room is designed to be non-descript, so the focus can be on the object search task and distractors do not affect the experiment. These colored geometric objects hover in space and represent the target and its distractors. Figure~\ref{fig:scene} shows the layout from above. Section~\ref{sec:stimuli} describes the objects. Objects vary in height and horizontal position within their assigned area, so search requires both coarse orientation toward a an object's area and finer search within it once the user's gaze approaches the vicinity of the object. The gaze-contingent agent knows the target identity and the user's gaze data but withholds the target's identity from the user; participants \textit{must} rely on the agent's auditory guidance to locate the target. To complete a trial, participants select the object by pointing the right-controller ray toward it and pressing the trigger. If the selection is correct, the trial ends. If it is incorrect, the participant can keep searching and select again until the trial's 25-second active-search limit expires.

\subsection{Stimuli}
\label{sec:stimuli}
The stimulus set consists of six geometric shapes, each presented in one of four colors, giving 24 shape--color identities. The sphere and cube are 8~cm across; the pyramid has a 10-cm square base and is 8~cm tall; the cylinder is 8~cm in diameter and 8~cm tall; the five-pointed star is 9.6~cm across and 4.8~cm deep; and the capsule is 9.1~cm long and 4.6~cm wide (Figure~\ref{fig:recorded-search-scene}c). Objects are rendered in red (\#E62626), blue (\#2659E6), yellow (\#F2D91A), and green (\#00A878), given as base colors before scene lighting.

Each trial is a conjunction search~\cite{treisman1980feature}: the target is the only object with its combination of shape and color, so neither feature alone identifies it. Of the 168 objects in a trial, 39 share the target's color but not its shape, 39 share its shape but not its color, and 89 share neither. Distractors are drawn from these pools and mixed across the planes so that no category is grouped together. Within 0.5~m of the target, every layout places five to eight objects, two to four of which share one of the target's features, with at least 0.2~m between object centers. Each of the 24 identities serves as the target exactly twice in each 48-trial voice block, so both voices search for the same set of targets.

\subsection{Voices}
\label{sec:voices}
Voice cloning, which replicates a speaker's voice from a reference recording, has become practical with recent instant-cloning methods~\cite{qin2023openvoice}. In this study, all voice audio is pre-synthesized with the commercial ElevenLabs service, which supplies the voices in both the SAV and the SSV conditions. To support the self-similar condition, the participant's spoken answers during the audio intake provide the samples for cloning. Participants hear a voice clip of each agent for the Selected Agent Voice condition and choose the one they prefer the most for their experiment . All voice clips are level-matched to have similar volume. The system logs the SAV, and voice clone settings per participant.

\subsection{Gaze-Contingent Guidance}
Prior guidance systems combine initial orientation with finer guidance toward the target~\cite{kwok2022twostep,tanaka2026coarse}. Spoken directions in Follow My Voice follow a similar progression.

The Follow My Voice system continuously collects eye-gaze origin, direction, and gaze validity; head pose; right-controller pose; and gaze ray-object intersections. A local state machine combines these observations with the target geometry to track the participant's progress through the search: turning toward the target plane, refining within the object plane, acquiring the target with gaze, pointing with the controller, and becoming ready to select. The gaze-contingent agent in Follow My Voice issues new gaze-dependent guidance only when gaze data are valid and recent.

\subsubsection{From Gaze to Spoken Direction}
\label{sec:guidance-geometry}
The direction for the next voice cue is first computed geometrically by the application before the decision model is ever consulted. Each valid gaze sample supplies an eye origin $\mathbf{o}$ and a gaze direction $\mathbf{g}$, and the target's position $\mathbf{p}$ is known at the start of each trial round. Both $\mathbf{g}$ and the target vector $\mathbf{d}=\mathbf{p}-\mathbf{o}$ are expressed relative to the seated forward direction, so the computation does not depend on how the room is oriented. A sample whose direction lies within about $12^\circ$ of straight up or down is treated as unusable rather than as a departure from the object plane, because left and right are undefined there. The eight object planes form a ring at $45^\circ$ intervals around the chair.

\paragraph{Notation.} Positions and directions are expressed in the world frame, whose $y$ axis points up, and all angles are reported in degrees. Two operations recur. The horizontal projection of a vector $\mathbf{v}$ is $\Pi(\mathbf{v})=(v_x,0,v_z)$, and its elevation above the horizontal plane is $\operatorname{elev}(\mathbf{v})=\operatorname{atan2}\bigl(v_y,\sqrt{v_x^2+v_z^2}\bigr)$. For two horizontal vectors $\mathbf{a}$ and $\mathbf{b}$, the signed horizontal angle from $\mathbf{a}$ to $\mathbf{b}$ is
\begin{equation}
\operatorname{yaw}(\mathbf{a},\mathbf{b})=\operatorname{atan2}\!\bigl(\hat{\mathbf{y}}\cdot(\mathbf{a}\times\mathbf{b}),\;\mathbf{a}\cdot\mathbf{b}\bigr),
\end{equation}
which lies between $-180^\circ$ and $180^\circ$ and is positive when $\mathbf{b}$ lies to the right of $\mathbf{a}$, that is, clockwise when seen from above. The same convention is used for every horizontal angle in this thesis.

\paragraph{Angular error.} During the search, the remaining horizontal (yaw) and vertical (pitch) errors between the gaze direction and the target are
\begin{equation}
\psi=\operatorname{yaw}\bigl(\Pi(\mathbf{g}),\Pi(\mathbf{d})\bigr),\qquad
\phi=\operatorname{elev}(\mathbf{d})-\operatorname{elev}(\mathbf{g}).
\end{equation}
The yaw error $\psi$ is positive when the target lies to the participant's right of the current gaze, and the pitch error $\phi$ is positive when the target is higher than the point of regard. Both are recomputed for every valid gaze sample. The starting angle $\theta_0$ of Section~\ref{sec:theta-measures} applies the same yaw measure once, from the readiness cross to the target, before the trial begins.

\paragraph{Turning toward the object plane.} Outside the target plane, the sign of $\psi$ selects ``left'' or ``right.'' When the target is nearly behind the participant ($|\psi|\geq150^\circ$), the first chosen direction is retained, so small head movements across the rear seam cannot reverse an instruction already given, and the remaining turn is measured along that route. Progress cues are earned in $45^\circ$ steps, one object plane at a time: crossing the same step again after turning back does not produce another ``keep going.''

\paragraph{Refinement within the object plane.} Inside the target plane, $\phi$ and $\psi$ are converted to one of nine directions: up, down, left, right, the four diagonals, or aligned. A vertical component is added when $|\phi|$ exceeds $3^\circ$, and a horizontal component when $|\psi|$ exceeds $5^\circ$. Once a component is being spoken, it persists until the error falls below $1.5^\circ$ vertically or $3^\circ$ horizontally, and an aligned state persists until the error exceeds $4.5^\circ$ vertically or $7^\circ$ horizontally. These separate entry and exit thresholds prevent small eye movements from flipping the instruction back and forth. They are development settings rather than values drawn from prior work. Within the object plane, the gaze ray must also intersect the object plane so that its vertical position can be measured; otherwise no new direction is issued.

\paragraph{Coarse-to-fine cues.} Guidance moves from coarse to fine, and yaw comes first. Outside the target plane, cues address only the horizontal turn, with wording such as ``Turn way left'' at $90^\circ$ or more and ``Keep turning left'' above $45^\circ$. Pitch enters once the participant reaches the object plane. The sign of $\phi$ decides whether a vertical cue is given, but its wording comes from a coarse measure: the height difference between the target and the point of regard, as a fraction of plane height. Up to 20\% of the object plane produces ``a little higher'' or ``a little lower,'' up to 50\% produces ``look higher'' or ``look lower,'' and larger differences produce ``look way higher'' or ``look way lower.'' Diagonal cues add the horizontal direction to the vertical one, as in ``a little higher and left.'' Short continuations such as ``a bit more'' follow measured progress near the target.

Figure~\ref{fig:phrase-stages} gives example wording at each stage. Both voices use the same phrases, and every phrase is prepared in advance for each participant.

\paragraph{Consistency with the visible highlight.} The object closest to the gaze ray, among those whose vicinity contains it, receives a visible highlight, on any plane. If a vertical instruction would contradict that highlight's position relative to the target, for example ``down'' when the target is above the highlighted object, the vertical component is dropped and only the horizontal component is spoken. The system never substitutes the opposite vertical direction.

\paragraph{Target acquisition.} New directional guidance stops once gaze has remained within the target's vicinity ring for at least 100~ms or the controller ray is on the target (Section~\ref{ch:measurement}). The phrases offered to the decision model are limited to those whose direction matches the computed one, and each selected cue is checked against a fresh evaluation of this geometry before playback (Section~\ref{sec:playback-control}).

\subsection{Decision Model}
\label{sec:decision-model}
Follow My Voice uses a small, fine-tuned language model to decide when and how the agent speaks. The model is based on MiniLM~\cite{wang2020minilm}, a compact transformer distilled from a larger language model, in its six-layer \texttt{all-MiniLM-L6-v2} sentence-encoder form~\cite{reimers2019sbert}, with about 22 million parameters. Unlike a large language model, it does not generate free-form text. It is fine-tuned as a classifier that chooses among a small set of guidance strategies, and a second fine-tuned copy ranks the prepared phrases that carry out the chosen strategy. Both voice conditions use the same model and the same phrase library.

\subsubsection{From a Cloud Model to a Local Model}
\label{sec:cloud-to-local}
Guidance decisions were initially made by Jev, a cloud-hosted large language model. Each decision therefore required a request to a remote service, and the resulting latency proved too high for guidance that must keep pace with the participant's head and eye movements. In the development sessions of October 19--20, 2026, for example, one gaze confirmation reached playback 2.19~s after the first qualified request, following repeated requests to the cloud model (Section~\ref{sec:development-results}). The cloud model was therefore replaced with the small local model described in this section, which answered roughly five to six times faster in comparable requests (Section~\ref{sec:small-local-model}). The change did not alter the application's geometry, phrase library, or playback checks. The local model is not a compressed copy of Jev: it was fine-tuned from the pretrained MiniLM checkpoint on synthetic states labeled by an authored reference policy, and Jev's responses were not used as training labels (Section~\ref{sec:model-training}).

\subsubsection{Choice of Base Model}
The base model was chosen for three properties of the task. First, guidance phrases are short spoken sentences, and many differ only in emphasis or degree, such as ``Turn right,'' ``Keep turning right,'' and ``A little more right.'' Sentence-BERT models are trained so that sentences with similar meanings receive similar representations~\cite{reimers2019sbert}, so the starting checkpoint already distinguishes and relates such variants. This prior knowledge allows a moderate amount of synthetic training data to suffice for both the strategy choice and the phrase ranking. Second, the six-layer model is small enough to answer within the time scale of head and eye movement on the lab computer's processor (Section~\ref{sec:small-local-model}). Third, an encoder that classifies and ranks can return only options it was offered. Every phrase is synthesized in advance in both voices, including the participant's clone, and cached on the headset, so a phrase the model selects always has recorded audio in both conditions. A generative model could compose a sentence for which neither voice has a recording, and the two conditions could then diverge in wording. The checkpoint is released under the Apache-2.0 license and pinned to a fixed revision, so the starting weights can be reproduced. Its pretraining on general English text carries no knowledge of the task geometry, which is one reason geometric rules and gating remain outside the model (Section~\ref{sec:overrides}).

\subsubsection{State Sent to the Model}
At each decision point, Unity assembles a structured state of the search. It records whether gaze evidence is valid and recent, whether the participant is inside the target plane, and whether target gaze or controller pointing qualifies. It adds the combined angular error to the target and its distance band, how that error has changed over the last few seconds (trend, net reduction, and gaps in tracking), the last cue and how the participant responded to it, the number of cues and wrong selections so far, the outcomes of previous trials, the time since speech ended, and the strategies currently allowed. Three fields give the model a sense of direction. \emph{Needed} is the direction Unity has computed to the target, such as left or up and right. \emph{Moving} is the recent direction of gaze over the last two seconds and whether it is toward, away from, or across that direction. \emph{Started} is a band for the trial's pre-cue angle and side, such as a large turn left, on the same plane, or behind. These use the same-trial snapshot and recent history only; they are marked unknown when the snapshot, the history, or tracking is missing. Because a language encoder handles words better than arithmetic, they are sent as words rather than numbers. The target's identity, shape, and color are never included. The model receives this state as a compact text description of at most 384 tokens.

\subsubsection{How the Model Decides}
The strategy head chooses one of seven options: observe for one second (stay silent and reassess), brief or explicit orientation toward the target plane, brief or explicit refinement within the object plane, correction, or encouragement. Unity offers only the strategies that are valid in the current situation, and the model can choose only among them. When the chosen strategy is to speak, the phrase ranker scores the prepared phrases offered for that strategy, taking into account how often and how recently each phrase has played, and the highest-scoring phrase is scheduled. The model's scores are used only to choose among the offered options; they are not calibrated probabilities.

\subsubsection{Why a Small Local Model}
\label{sec:small-local-model}
Guidance has to keep pace with head and eye movements that change within a fraction of a second, and a cue that arrives late can send the participant somewhere they have already looked. The model therefore runs on the lab computer beside the headset and answers over a local connection. In development measurements on that computer, a complete two-stage decision (strategy and phrase) over the local connection had a median of about 34~ms (95th percentile 41~ms), and a direct call to the strategy model about 7~ms. For the first phrase on reaching the target plane, the local model responded in 171~ms, whereas the cloud large language model previously used for these decisions, Jev, responded in 820~ms in a single comparable request; an earlier local version showed a median of 30~ms against 182~ms for the cloud model. These timings were taken on the desktop and do not include headset networking or the onset of audible speech. Running locally also keeps decisions during the task on the lab computer, and because the model can only select among prepared phrases, it cannot produce unexpected wording.

\subsubsection{Deterministic Overrides}
\label{sec:overrides}
Guidance is otherwise driven entirely by the model; fixed rules take precedence only in a few specific situations. No decision is requested when gaze is invalid, when the participant is already looking at or pointing at the target, when the guidance state is not a search state, or when audio is not ready, and a server-side gate forces silence under the same conditions. On the first arrival at the target plane in each trial, the strategy is fixed to an explicit refinement and the model chooses among four phrases that confirm the area and give the remaining direction, such as ``Right area. Look lower and right.'' When the participant reverses direction, an obsolete cue is faded out without replacement. A reminder plays only at the 25-second deadline when the participant is already on the target, and trial openings, target confirmations, and success feedback come from prepared local phrases. Only one request may be pending, requests are at least 0.75~s apart, and any decision older than 3.25~s or no longer matching the participant, trial, voice, or policy version is discarded. If a request fails, the agent stays silent and retries rather than falling back to another provider.

\subsubsection{Short-Term Memory}
The state includes a short-term memory of the participant's behavior. A spatial history samples the error to the target every 0.5~s over the last 12~s and is cleared when tracking is lost for more than 1.25~s. A cue history keeps the last eight cues in the trial and the participant's response to each, measured as the change in error over the following 3~s. A phrase history records how often and how recently each phrase has played, and summaries of the previous six trials carry information across trials. Trial-level memory resets at each new trial and participant-level memory at each new participant. A separate speech memory of the last four speech events within 15~s supports the playback checks described below.

\subsubsection{Training}
\label{sec:model-training}
The model was trained on synthetic decision states generated to cover the situations guidance must handle: stalled, receding, oscillating, steady, and mixed search trajectories, departures from the target, different silences and numbers of prior cues, and failures of the gating conditions. The scenarios came from a seeded generator written with the help of a large language model coding assistant, and they were revised against real development trials. For example, an early model missed departures from the target seen in recordings, so the data were rebuilt to cross departure events with every trajectory pattern, and examples of long-way turns that could not occur in Unity were corrected. Each state was labeled by an authored reference policy, so that the model learns to reproduce that policy quickly from the compact state. Individual recorded states were not used as training examples; real development recordings were kept as regression tests for the strategy stage. The current version continues earlier weights with the direction fields added. The strategy model was fine-tuned with AdamW for six epochs on 2,240 training states balanced across the seven strategies, with 448 validation and 448 test states generated with different sampling cadences and combined gate failures, and the phrase ranker for four epochs on 768 training examples, with 160 for validation and 160 for testing. The authored policy uses direction in two situations: briefly observing a recent turn along the cue that goes the long way around, and preferring an explicit cue when the participant is moving away in the opposite direction. On the new test set, the strategy model agreed with the reference policy on 433 of 448 states (96.7\%; 435 of 448, or 97.1\%, after the deterministic gates), compared with 391 of 448 (87.3\%) for the previous version without direction. The phrase ranker agreed with its reference on 153 of 160 cases (95.6\%) and avoided repeating a phrase in all 78 opportunities to do so. On the previous version's test set, the new model agreed on 431 of 448 states, against 424 for the previous version. Because the synthetic data were revised during development, these sets are held-out development evidence rather than an untouched evaluation, and the new test set was built to include situations the previous input could not separate. The model also still failed the three fixed test cases of a long-way turn along the cue, so it does not reliably recognize them. These figures measure agreement with the authored policy, not usefulness to participants, which the user study will assess.

\subsection{Playback Control}
\label{sec:playback-control}
Because decisions arrive asynchronously, the participant's state may change before a decision returns. A local speech scheduler therefore revalidates each decision against the current state, evidence, pacing, and object intersections before playback, and discards decisions that are stale or conflict with the current situation. Qualified gaze and controller acknowledgments, together with eligible turn-progress milestones, can be handled locally and played from prepared phrases without waiting for a new model decision. These local cues remain subject to the same checks. When a qualified target acknowledgment would replace misleading search speech, a local fast path avoids waiting for interruption advice. This path protects the first 0.35 seconds and final 0.5 seconds of the current phrase, retains a 2.5-second interruption cooldown, and fades the audio over 150 ms. The fast path keeps the separate gaze and controller hold requirements, and fresh evidence is checked before the fade, after it, and at playback. Setup, completion feedback, and existing acknowledgments are protected from interruption. Each completed or interrupted utterance updates both the memory and the event log. Model latency, deferral, cancellation, fallback, and playback onset are logged separately to support delay attribution. When a trace lacks the required events, the source of a delay is recorded as unknown rather than inferred from the spoken phrase alone.

The model's decision is based on an earlier snapshot, so it is treated as advice. A decision to speak results in playback only if the cue passes current-state checks. Provider-selected phrases and qualified local feedback both pass these checks before the prepared clip starts. Readiness and pacing are checked during scheduling, and the queued relevance callback is evaluated again immediately before audio playback. The same local gate applies to every strategy the model can choose.

\subsubsection{Delivery Quality as an Experimental Requirement}
Both voice conditions use the same versioned guidance mechanism, although delivered sequences depend on participant behavior and clips may differ acoustically. Voice identity, library metadata, playback onset, and delivery faults are therefore recorded so that each can be traced to its condition.

This record matters because a delayed or confusing cue could alter search performance or a participant's judgment of the voice and then be mistaken for an effect of voice condition. Appendix~\ref{app:scenarios} defines guidance sequence tests and an evaluation rubric for checking the implementation.

\label{sec:trial-review}
