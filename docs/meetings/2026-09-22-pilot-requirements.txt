PROJECT GOAL

We are building a research experiment investigating whether a SELF-SIMILAR synthetic voice — a cloned version of the participant’s own voice — changes visual search behavior, task performance, gaze behavior, arousal-related eye metrics, cognitive workload, or subjective experience compared with a voice the participant explicitly PREFERS.

The experiment runs in XR/VR with eye tracking.

The current comparison should be:

PREFERRED VOICE
vs.
SELF-SIMILAR / CLONED VOICE

This supersedes older assumptions that the primary comparison is simply “generic voice vs cloned voice.”

The study uses a within-subject design for voice condition with counterbalanced block ordering.

Do not change research methodology casually. Flag decisions that require researcher approval.

1. PREFERRED VOICE SELECTION

Implement or enhance the preferred-agent-voice selection workflow.

Participant should hear a limited curated set of candidate voices rather than receiving an arbitrary generic voice.

Requirements:

* Support approximately 5–6 candidate voices per applicable voice group.
* Candidate voices should be compatible with the participant’s voice/gender matching strategy.
* Avoid cross-gender voice differences becoming an uncontrolled confound.
* Participant can preview each candidate voice.
* Collect a preference score for EVERY candidate voice.
* Use a 0–100 or 1–100 preference scale.
* Also capture the participant’s ranking of the candidate voices.
* Determine and persist the participant’s highest-ranked/preferred voice.
* Store the exact voice ID used.
* Store all ratings, not only the winning voice.
* Preserve enough metadata to reproduce which voices the participant evaluated.

If a generic-voice-selection feature already exists, MODIFY it into this preferred-voice workflow rather than building a parallel system.

Review the existing voice-recording and voice-cloning workflow.

7. OBJECT SELECTION — CONTROLLER RAYCAST

Review the current selection mechanism.

The preferred architecture from the latest design discussion is:

EYE GAZE = PASSIVE MEASUREMENT

CONTROLLER RAYCAST + TRIGGER = EXPLICIT OBJECT SELECTION

Participant visually searches naturally.

Eye tracking measures their visual behavior without requiring gaze itself to trigger selection.

Then:

* participant points controller ray at desired object,
* participant presses/holds trigger,
* selection is confirmed.

If the existing implementation uses gaze-dwell selection, refactor intelligently rather than leaving two competing selection systems unless there is a deliberate configuration flag needed for testing.

Keep eye gaze completely instrumented even though it is no longer the primary selection input.

14. GROSS MOVEMENT / ROTATION

Do not calculate movement solely as endPosition - startPosition.

We care about cumulative movement.

Conceptually:

gross movement = sum of absolute frame-to-frame movement.

Likewise for rotation.

Calculate or make it possible to derive:

* total gross head rotation
* yaw rotation
* pitch rotation
* roll rotation
* total translation
* X translation
* Y translation
* Z translation

Be careful with Euler angle wraparound.

If quaternions are already available, preserve them in raw telemetry and derive human-readable rotational metrics appropriately.

Do NOT implement simplistic math that produces giant false rotations when crossing ±180 degrees.
