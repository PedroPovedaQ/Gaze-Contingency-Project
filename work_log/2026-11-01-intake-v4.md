# Intake v4 and continuous session monitor

## Implemented

Protocol **audio-intake-v4-20261101** follows e623f4a, preserving automatic fit and participant numbering. New sessions contain nine prompts; historical sessions retain their stored version/questions/transcripts and read-only historical review. The exact final prompt list is in [guide 10](../docs/guide/10-audio-intake.md). Q4 uses the required seated/right-controller wording; Q8 asks only about current correction. Handedness is absent from new-protocol UI, coding and transcript exports. River Q4/Q8 clips use the existing exact-text cache and are generated on first authorized use; no live prompt generation was performed here.

Save eligibility review first saves any pending transcript/coding edit with the same correction provenance and retained machine original as the correction button. Failed correction stops review. Initials and four positive answers remain required.

The six steps are Reserve, Consent, Selected Voice, Audio intake, Eligibility review, Send to headset. With a recorded consent receipt, all nine prompts and at least 30 seconds/50 words, clone then cache start automatically while review continues. Fallback reading remains available below threshold. Compact status/retry replaces the clone/cache step. Negative/unclear review or withdrawal stops new work; a known clone is deleted through the ElevenLabs DELETE voice path and recorded. Late clone returns are cleaned up; deletion errors remain visible/retryable. Positive review and verified transferred cache gate assignment. An already submitted provider request cannot be recalled; unknown outcomes stay uncertain instead of retrying automatically. Endpoint reference: [ElevenLabs delete voice](https://elevenlabs.io/docs/api-reference/voices/delete).

The persistent monitor uses the existing bridge/2 Hz heartbeat and starts with the intake connection without a manual Live-mode toggle. It remains over intake and other views, shows setup/audio/gaze dots/verification/instructions/practice/readiness/opening/search/feedback/break/block 2/completion, timestamps, completed trials, voice, gaze, faults and link age. It warns on stale updates, focus/pause or available wear signal. First-person reconstruction accompanies fresh trial poses; it is telemetry reconstruction, not streamed pixels. No new monitor command/channel or study-clock mutation. Displayed elapsed time restarts with a headset process epoch; logs retain its ID.

New timestamped screen transitions live in PreparationLogs/session-<desktop ID>/screen-transitions.jsonl and are archived through the existing receiver. Readiness, opening cue/direction, trial search/selection/timeout, block checkpoints and final handoff already had trial/replay records. The sidecar adds pre-trial screens and a unified flow sequence. Missing/offline screens are not inferred.
